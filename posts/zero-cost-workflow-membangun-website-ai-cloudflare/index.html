Zero-cost workflow: Membangun website profesional dengan AI agents dan Cloudflare

Membangun web app profesional dari nol tanpa boilerplate. Cukup dengan versi gratis Gemini, Lovable, OpenCode, dan Cloudflare.

Membangun web app dari nol biasanya berarti menghabiskan waktu berhari-hari berhadapan dengan boilerplate, men-setup deployment pipeline, dan tweaking CSS. Namun dengan workflow yang tepat di zaman AI yang makin hair makin cerdas, proses ini bisa di-skip sepenuhnya.

Teori atau konsep diatas coba saya buktikan sendiri saat membuat website ukurdampak.id, website page untuk company profile jasa konsultan SROI milik istri saya. Website ukurdampak hanya sebagai studi kasus, tapi blueprint ini bisa kita pakai untuk mem-bootstrap project website apa pun secara gratis.

Saya mengkombinasikan Gemini, Lovable, OpenCode Z, dan Cloudflare untuk membangun keseluruhan frontend, melakukan hardening pada UX, dan deployment ke production.

Zero cost AI-driven workflow#

Jika development umunya mengikuti repetisi plan - write - test - debug, workflow yang saya pakai di sini tidak begitu beda. Hanya saja saya banyak melibatkan AI. Saya generate dulu dari AI, refine hasilnya, lalu harden sampai layak production, kemudian ulangi lagi prosesnya.

Prototyping dengan Gemini dan Lovable#

Kita tidak dapat menggunakan prompt untuk membangun production app yang utuh dalam satu percobaan. Jika kita mencoba membangun full application dalam satu chat context, LLM perlahan akan kehilangan konteks dan me-degrade logic atau intent dari prompt yang kita gunakan.

Sebagai gantinya, dalam flow ini saya memisahkan proses thinking dari proses scaffolding.

Saya menggunakan Google Gemini Free secara spesifik untuk riset dan refinement konten. Context window-nya cukup besar untuk menampung seluruh draf kasar ide saya sekaligus, sehingga cocok dipakai untuk mematangkan content model sebelum menyuruh AI lainnya menulis kode apa pun.

Setelah konsepnya solid, saya meminta dibuatkan prompt yang kemudian saya gunakan sebagai prompt awal ke Lovable, tentunya Lovable dengan free credit. Lovable bertindak sebagai visual React scaffolding engine. Tools ini mengambil structured prompt dan me-generate component tree awal. Layout React-nya jalan, tapi UX-nya standar dan kaku. Selain itu, free creditnya juga tidak memungkinkan untuk melakukan iterasi hingga hasilnya memuaskan.

Pada titik ini, saya men-sync generated code tersebut ke GitHub dan men-pull ke local. Browser-based AI generation berhenti di sini.

Menghilangkan AI-Slop dengan Local AI Harness#

Masalahnya, output AI untuk UI itu punya ciri khas yang langsung kelihatan. Palet warna gradient yang sangat khas, spacing yang sangat umum, serta copy/content yang terlalu generic. Untuk memperbaikinya, saya berpindah ke OpenCode untuk local development. Saya menggunakan OpenCode Z dengan free model yang bagi saya sudah sangat cukup untuk kebutuhan sehari-hari. Pada case ini, saya banyak menggunakan model MiMo V2.5 Free.

Browser-based AI editors sangat bagus untuk memulai, tapi saya rasa mereka kesulitan dengan deep repository context. OpenCode berjalan secara local dan berinteraksi langsung dengan file system yang kita punya, dalam hal ini adalah file system dari repo yang sudah kita clone yang sebelumnya dibuatkan oleh Lovable.

Saya menggunakan dua OpenCode skills spesifik untuk membuang “AI slop” dan membuat interface-nya terasa intentional:

/hallmark#

Saya gunakan untuk menghandle structural redesign. Ia memaksa standar anti-generic UI, memperbaiki layout hierarchy, dan mengaplikasikan design constraints yang nyata.

Quote

Hallmark picks a macrostructure for the brief, dresses it in one of twenty-one themes, runs fifty-seven slop-test gates plus a pre-emit self-critique, and refuses the on-distribution defaults every LLM was trained into.

— Repo1

/impeccable#

Lebih complex dan granular dibanding Hallmark, skill ini saya gunakan untuk fokus berbeda: micro-interactions, accessibility, dan visual hardening. Bagian yang biasanya saya skip dan memang tidak begitu paham jika mengerjakan sendiri, dari sisi konsep dan praktikalnya.

Quote

Turn AI slop into interfaces you’re proud to ship. Impeccable gives your agent the design expertise to build from scratch, improve what you have, and stay true to your design system.

— Site2

Chrome Dev Tools AI#

Ketika saya menemukan layout bugs atau perlu memperbaiki masalah DOM spesifik, saya menggunakan Chrome Dev Tools AI untuk me-generate targeted prompt fixes, lalu me-feed hasilnya kembali ke OpenCode. Loop inspect di Chrome lalu fix di OpenCode ini jauh lebih cepat dan efisien daripada mencoba menjelaskan visual bugs ke chat interface, ataupun meminta AI untuk menggunakan headless browser untuk melakukan debug.

Paralel dengan proses hardening UI, saya juga memperbaiki konten website, lagi-lagi masih menggunakan Gemini Free. Fokusnya di SEO: memperbaiki heading structure, menulis meta descriptions yang lebih targeted, dan me-refine copywriting agar mengandung keyword yang relevan tanpa terasa dipaksakan.

Serverless forms#

Website ini dirancang sebagai funnel baru untuk memperoleh klien, sehingga integrasi contact form di luar email menjadi hal yang penting. Tapi karena frontend sepenuhnya statis, sementara mengoperasikan backend Node menambah satu komponen database hanya demi menangani formulir kontak terasa terlalu overkill jadilah saya perlu mencari solusi yang pas dengan nol cost.

Lagi-lagi, mengoptimalkan apa yang ada dan disediakan gratis oleh Cloudflare. Code dari repository di-build dan di-deploy langsung ke Cloudflare Pages. Untuk menghandle dynamic form submissions tanpa database, saya menggunakan edge network dari Cloudflare.

  1. Cloudflare Turnstile memblokir bot traffic. Tidak seperti reCAPTCHA, Turnstile menggunakan privacy-preserving proof-of-work3 challenges. User hampir tidak pernah harus meng-klik gambar lampu lalu lintas atau menebak-nebak apakah sedikit bagian dari roda dapat dianggap sebagai kendaraan.
  2. Sebuah Cloudflare Worker meng-intercept form submission. Workers berjalan di atas V8 isolates4, bukan containers, yang berarti cold starts hampir tidak ada.
  3. Worker memformat data menjadi JSON payload dan mem-push-nya langsung ke Telegram chat via Telegram Bot API.

Kenapa Telegram? Saya sempat mempertimbangkan sekadar menaruh link ke Google Form terpisah. Sangat praktis, tapi UX-nya memotong journey pengunjung dan terasa kurang profesional. Sempat juga terpikir melempar payload ini ke Airtable API, tapi jelas overkill dan klien (istri saya) tidak familiar dengan ekosistem tersebut.

Pilihan akhirnya jatuh ke Telegram. Istri saya sudah menggunakannya sehari-hari. Plus, notifikasi push real-time di handphone memungkinkan respons ke calon klien yang jauh lebih cepat dibanding harus me-refresh inbox email secara berkala.

Melindungi free-tier overlimit karena bot#

Satu risiko utama pakai arsitektur serverless gratisan adalah exhaustion attack. Kalau ada bot yang terus-menerus men-spam, dalam kasus ini adalah endpoint contact, kuota request per hari5 dari Cloudflare Workers bisa habis seketika, dan rate limit API Telegram akan kena blokir.

Untuk mencegah ini, validasi Turnstile wajib dipasang di dua sisi:

  1. Client: Form dikunci dan tidak bisa di-submit sampai lapisan anti-bot merespons dengan token yang valid. Pendekatan ini secara efektif memblokir 99% bot sederhana yang berjalan tanpa mengeksekusi JavaScript.
  2. Server: Di sisi server, token tersebut diekstrak dan diteruskan ke Cloudflare untuk divalidasi. Sistem mengecek status keberhasilan, jenis aksi, dan kecocokan hostname. Jika token terbukti tidak valid, request langsung di-abort dengan status 403 sebelum sistem mencoba meneruskannya ke Telegram.

Dengan setup ini, kuota gratisan Worker kita aman. Bot tertahan di frontend, dan script otomatis yang mencoba mem-bypass frontend akan langsung ditolak di eksekusi baris pertama Worker.

Berikut alur verifikasi gandanya:

sequenceDiagram
    participant U as User/Bot
    participant F as Frontend
    participant T as Turnstile API
    participant W as Worker
    participant TG as Telegram API

    U->>F: Submit form
    F->>W: POST /api/submit-form + Token
    
    W->>T: Verifikasi Token + Secret Key
    
    alt Token Invalid
        T-->>W: success: false
        W-->>F: 403 Forbidden (Bot diblokir)
    else Token Valid
        T-->>W: success: true
        W->>TG: POST /sendMessage
        TG-->>W: 200 OK
        W-->>F: 200 OK (Pesan terkirim)
    end

Untuk waktu pengerjaan, dari proses prototyping ke proses deployment memakan waktu ~4 hari saja. Saya kerjakan tiap weekend dan tentu saja masih nyambi mengerjakan hal lain.
